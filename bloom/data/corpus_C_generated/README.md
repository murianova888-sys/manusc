# Corpus C: Bloom-labelled discrete mathematics questions (LLM-generated)

480 English discrete mathematics questions with Bloom's taxonomy levels.
The questions were generated by Claude (Anthropic) as a supplement to the 500-item template bank
(Corpus A) and do not overlap with it.

## Composition

16 topics × 6 levels × 5 questions. Every topic appears at every level, so the topic no longer reveals the level.

Topics: propositional logic, predicate logic, set theory, relations, functions, combinatorics, graph theory,
trees, Boolean algebra, proof techniques, number theory, recurrence relations, finite automata,
partially ordered sets, equivalence relations, algorithms.

## Files

- `bloom_questions_generated.csv` / `.jsonl`: the full dataset (UTF-8).

## Fields

| Field | Description |
|---|---|
| `id` | GEN001…GEN480 |
| `question` | question text (model input) |
| `topic` | topic |
| `bloom_level`, `bloom_level_id`, `bloom_level_ru` | label: Remember (1) … Create (6); `bloom_level_ru` is the level name in Russian |
| `first_word` | first word of the question (for leakage analysis; do not feed to a model as a feature) |
| `n_words` | question length in words |
| `split` | train / validation / test, stratified by topic × level (3/1/1 per cell, seed = 42) |
| `source` | generated |
| `label_source` | `author_assigned_needs_review`: the label is the level requested from the generator; it was not reviewed by experts at generation time |

Split sizes: train 288, validation 96, test 96; all levels are equally represented in each split.

The audited labels (annotator M) and the rule-based rubric labels (annotator R) are in
`analysis/out/generated_with_audit.csv`.

## Comparison with Corpus A

| | Corpus A (500) | Corpus C (480) |
|---|---|---|
| Unique wordings | 48 | 480 |
| Distinct first words | 6 | 61 |
| Topic × level cells filled | 48 of 96 | 96 of 96 |
| Level recovered from the first word (test split) | 100% | 88.5% |
| Concrete mathematical content | no | yes |

Wordings deliberately overlap across levels: e.g. "Evaluate the Boolean expression…" is Apply, while
"Evaluate this claim…" is Evaluate; "Construct a truth table" is Apply, "Construct a bijection" is Create.

## Limitations

1. **Labels were assigned by the generator.** Boundaries between adjacent levels (Apply/Analyze,
   Analyze/Evaluate) are debatable; see the audit in `analysis/`.
2. **The verb remains a strong cue.** The rule "first word → most frequent level" reaches 88.5% on the test split.
   This is partly built into Bloom's taxonomy, which is defined through action verbs. Models should be compared
   against this baseline, not only against chance (16.7%).
3. **Single source.** The wording style is homogeneous, so models may transfer poorly to questions written by
   real instructors.
4. Mathematical correctness was checked on a sample basis; answers are not provided.
